from .nodes import preprocess_companies, preprocess_shuttles (ajouter les deux)  # noqa

a node is a mapping between a python function and some inputs and output

def create_pipeline(**kwargs) -> Pipeline:
    return Pipeline(
        [
            Node(
                func=preprocess_companies,
                inputs="companies",
                outputs="preprocessed_companies",
                name="preprocess_companies_node",
            ),
            Node(
                func=preprocess_shuttles,
                inputs="shuttles",
                outputs="preprocessed_shuttles",
                name="preprocess_shuttles_node",
            ),
            ...,
        ]
    )

Note :
À cette étape, le pipeline s’exécute correctement : Kedro transmet les datasets d’entrée aux fonctions définies dans les nodes, 
puis récupère les sorties produites.
Comme les datasets de sortie (preprocessed_companies et preprocessed_shuttles) n’ont pas encore été déclarés dans le catalog.yml, 
Kedro les gère temporairement en mémoire pendant l’exécution. 
Les résultats existent donc bien pendant le run, 
mais ils ne sont pas sauvegardés sur disque et sont perdus à la fin du pipeline.
Cette étape permet surtout de valider la logique de transformation 
avant de configurer explicitement le stockage des sorties dans le catalogue de données.
